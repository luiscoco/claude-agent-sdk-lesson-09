# Classroom walkthrough

Allow 20–25 minutes. Start without a key; use live verification only for the optional real SDK comparison.

1. **Inventory the historical sample.** Analyze the default example. Locate the old package, historical session call and TodoWrite tool-list pattern. Explain why the lesson's migration recommendation does not imply TodoWrite was removed from 0.3.310.
2. **Review status labels.** Load the alpha pattern. Compare alpha helpers with historical session flow. Alpha means developing, not deprecated or required. Read the installed contract before adopting an experimental entry point.
3. **Fix the executable shape.** Load conceptual slide syntax and find top-level configuration findings. Compare the modern preset and expand the compile-checked reference. Configuration belongs in `options`; the historical package dependency is not installed or executed here.
4. **Plan a staged migration.** Mark the inventory step, then edit the sample. The checklist must become unavailable until re-analysis. Change the source version and repeat. The export records a fingerprint and manual attestations rather than certifying behavior.
5. **Check task semantics.** Run the synthetic task scenario, then identify what is still unproved. With a configured key, run actual cold verification. Check that TaskCreate/Update/Get/List each execute and the read/list results confirm completion. A green final SDK outcome without those checks is insufficient.
6. **Check permissions.** Run the denial scenario. With a key, verify the host policy was invoked and the protected handler count is zero. Explain why pre-approved task tools do not reach `canUseTool`, and how ownership guards still constrain their inputs.
7. **Adopt alpha startup separately.** After the baseline works, opt into prewarm and run the same fixed reference. Identify preparation, claim settlement, execution and cleanup events. Explain why `option_not_applied` must not cause an automatic duplicate cold run.
8. **Inspect settings deliberately.** In the Alpha lab, opt into the actual helper. Compare project-only and project-plus-local fixtures. Read the raw-mode caveat. Never treat a diagnostic settings merge as permission to perform an action.
9. **Record evidence.** Export the audit, manual review and fixed-reference report. Identify each item's source: parsed code, learner attestation, synthetic fixture or actual SDK observation. Complete the four-question quiz.

## Instructor answers

- Experimental/alpha means a developing surface requiring deliberate adoption. Historical/deprecated guidance recommends moving away from an older pattern; verify the actual version's exports before claiming removal.
- The task mapping is TaskCreate, TaskUpdate, TaskGet and TaskList; it requires behavior-level verification, not a blind string substitution.
- The installed query signature is `query({ prompt, options: { ... } })`.
- Migrate the historical unstable_v2 session pattern toward a retained query handle with async iteration and explicit cleanup.
- A successful answer does not prove permissions or task state. Inspect actual callbacks, handler counters and tool outcomes.
- `option_not_applied` can mean the claimed prompt is already running; inspect the existing query and avoid a duplicate run.
- `resolveSettings()` returns the raw cascade. This sample projects selected fields and never applies that diagnostic result as a live access policy.
